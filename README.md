# AI Project Executor

> **В этом репозитории спецификация продукта, кода здесь нет.**
> Описано, что система делает и как себя ведёт: экраны, типы документов,
> режимы исполнения, статусы, обработка ошибок, границы продукта.
> Работающая реализация того же брифа лежит в
> [Claude_code.-project-crm](https://github.com/Aleksandr-Litvinenko/Claude_code.-project-crm).
> Чем два решения отличаются и зачем нужны оба, разобрано в [COMPARISON.md](COMPARISON.md).

AI Project Executor — внутреннее веб-приложение для 1С-консультанта. В нём ведут проекты и ставят задачи на даты, а ИИ-агент в назначенное время готовит документ и отправляет его в Telegram.

## Зачем

На внедрениях 1С постоянно нужны одни и те же документы: уставы, технические задания, коммерческие предложения, протоколы, статусные отчёты, уведомления. Консультант заранее ставит задачу с датой, складывает контекст в чат задачи и в срок получает готовый документ, ничего не запуская вручную.

## Возможности

- Проекты с клиентом, описанием и списком конфигураций 1С.
- Задачи с типом документа, датой, режимом исполнения и повторяющимся расписанием.
- Дашборд на две недели: даты по строкам, проекты по колонкам, задачи в ячейках.
- Раздел «Задачи и проекты» с фильтрами, сортировкой и удалением.
- Чат задачи, из которого агент берёт контекст.
- История исполнений каждой задачи и общий журнал по всем проектам.
- Настройки Telegram и Anthropic; токены в интерфейсе не показываются.

## Дашборд

Главный экран показывает ближайшие две недели. Строка — дата, колонка — проект, в ячейках задачи. По такой сетке сразу видно загрузку, дыры в плане и ближайшие автоматические запуски. Недели переключаются, текущий день подсвечен, проекты визуально различаются. Из пустой ячейки можно создать задачу на этот проект и эту дату.

## Проекты и задачи

В разделе «Задачи и проекты» создают и удаляют проекты и задачи. Список задач фильтруется по статусу (невыполненные, выполненные, все), по проекту, по периоду создания и по периоду исполнения. Таблицу можно сортировать по любому столбцу: статус, название, проект, тип документа, дата задачи, дата создания, режим.

Карточка проекта показывает название, клиента, конфигурации и связанные системы, описание, задачи проекта с прогрессом и быстрые действия: запустить, изменить или удалить задачу.

## Карточка задачи

Слева параметры задачи и история исполнений, справа чат. В чат пишут всё, что должно попасть в документ: уточнения, требования, вводные, контакты, бюджет, риски, решения совещаний. Агент читает его перед генерацией.

## Типы документов

| Тип | Что получится |
|---|---|
| `CHARTER` | Устав проекта |
| `TZ` | Техническое задание на внедрение или доработку 1С |
| `KP` | Коммерческое предложение |
| `REPORT` | Статусный отчёт по проекту |
| `PROTOCOL` | Протокол моделирования или рабочего совещания |
| `NOTIFICATION` | Короткое сообщение в Telegram без DOCX |
| `COMBINED` | DOCX и отдельный текстовый анонс в Telegram |

У каждого типа свой промпт с нужной структурой, стилем и обязательными разделами.

## ИИ-агент

Перед генерацией агент собирает контекст: название и клиента проекта, конфигурации 1С, описание, все задачи проекта со статусами, параметры текущей задачи, сообщения из её чата, тип документа и режим исполнения. Документ пишется деловым языком проектов внедрения 1С. Если данных не хватает, агент помечает пробелы как требующие уточнения и не подставляет выдуманные проектные данные.

## Запуск по расписанию

Задача запускается в назначенную дату или по повторяющемуся расписанию. Планировщик регулярно ищет задачи, готовые к запуску, и берёт их в работу. Задача переводится в работу атомарно, поэтому при нескольких экземплярах приложения её не выполнят дважды. После успешного запуска повторяющейся задачи считается следующая дата, и задача возвращается в очередь.

## Режимы выполнения

- **AUTO**: агент генерирует документ и сразу отправляет его в Telegram.
- **CONFIRM**: агент отправляет в Telegram превью и ждёт решения. Результат можно принять или вернуть на доработку. Во втором случае задача снова ждёт запуска: в чат можно дописать правки и сгенерировать документ заново.

## Telegram

Через Telegram приходят готовые DOCX, короткие уведомления без файла, превью на подтверждение с inline-кнопками «принять» и «отклонить» и алерты об ошибках. Chat ID вручную вводить не нужно: достаточно указать токен бота, написать боту любое сообщение и запустить поиск чата в настройках.

## DOCX

Если документу нужен файл, ответ агента превращается в DOCX с заголовками, подразделами, списками, таблицами, выделением текста, стандартным оформлением листа и понятным именем файла. Файлы привязаны к конкретному исполнению и скачиваются из истории задачи и журнала исполнений.

## Статусы задач

`PENDING` ждёт запуска, `RUNNING` выполняется, `WAITING_APPROVAL` ждёт подтверждения, `DONE` выполнена, `FAILED` завершилась с ошибкой. Статус виден на дашборде, в таблицах задач, в карточке задачи и в журнале.

## Журнал исполнений

Общая история работы агента по всем задачам: дата запуска, задача, проект, статус, длительность, есть ли файл, текст ошибки. По журналу ищут неудачные генерации, проверяют отправки и скачивают документы.

## Ошибки и повторы

Ошибка генерации или интеграции записывается в исполнение, и задача получает соответствующий статус. Ошибки API повторяются автоматически. При критическом сбое в Telegram приходит алерт с названием задачи, проектом, текстом ошибки и временем.

## Сценарии

**Устав проекта.** Консультант создаёт проект и задачу «Написать Устав проекта», ставит дату и пишет в чат контакты, бюджет, сроки, риски и участников. В срок агент готовит устав и присылает его в Telegram.

**ТЗ на интеграцию.** В задаче описаны направления обмена, системы-участники, объекты 1С и особенности API. Агент пишет ТЗ со структурой AS-IS и TO-BE, функциональными требованиями, объектами 1С, интеграциями и оценкой трудозатрат.

**Еженедельный отчёт.** Повторяющаяся задача по расписанию собирает статусный отчёт из задач проекта и комментариев в чате.

**Подтверждение перед отправкой.** В режиме CONFIRM агент сначала присылает превью. Его подтверждают или отклоняют, дописывают правки в чат и генерируют документ заново.

## Для кого

Для небольшой внутренней команды из 1–3 человек, которые ведут внедрения 1С и регулярно готовят проектную документацию. Основной пользователь — консультант или руководитель проекта, которому нужно быстро собирать документы из накопленного контекста.

## Границы продукта

Приложение планирует проектные задачи, генерирует документы и доставляет их в Telegram. Продаж, бухгалтерии и управления ресурсами в нём нет, корпоративную CRM или ERP оно не заменит.
